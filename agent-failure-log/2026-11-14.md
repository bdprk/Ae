## movewalk 的 `?` 截断让 CFG move 验证长期失效（M2.4 recorder 依赖它才暴露）

- 时间：2026-11-14 15:10 (Asia/Shanghai)
- 任务：为 alloc 基准 workload 探明 drop 精化效果时发现 `total + sink(a)` 的 move 未被记录。
- 现象/报错：`Assign(0, Binary(...))` 的 statement_move_effects 返回 moved: []；`total = sink(a)`（无 Plus 链）正常记录 [1]。`total + sink(a)` 后 print(a) 的 use-after-move 只被 parser 拒绝，movewalk 的 Checked 验证从未报分歧。
- 已尝试：五轮插桩（enter/read/Binary/after-a/after-b/RECORD START/VERIFY 标签）逐层缩小，最终确认 Binary 臂的 `walk_expr(a, moved)?` 在 read 返回 None 时立即 `return None`。
- 原因判断：`?` 在 Option 上是「None 即整个函数返回」，而普通读取恰好返回 None——二元表达式的第二个操作数、Call 的后续参数、Store 的 value、If/While 的 body、walk_statements_reads 的第二条语句全部从未被 walk。该 bug 在 M2.4 之前就存在（13b3444 亦如此），但 movewalk 当时是 verification-only（parser 自己的 registers 强制安全），截断只是让验证空转；M2.4 的 recorder 依赖完整 walk 记录 move，截断直接让 elision 失效（保守但次优）。
- 教训/下一步：(1) `expr?` 用于「传播违例」的模式必须用 `if let Some(v) = ... { return Some(v) }`，Option 的 `?` 会把正常 None 当作提前退出；(2) verification-only 的 pass 长期与真实消费者脱节，等它变成 load-bearing 时才暴露，新消费者接入前要为旧 pass 补正确性测试（本次以 alloc workload 的 kept=3 vs 预期 kept=1 为线索）；(3) 修复后 Checked 更完整——与 parser 的 agreement 仍成立（275 测试 + fuzz 40 seeds + verify_generated_c 41 全过，无 internal error）。

## 视图绑定可重赋值打破 region 数学的 declare-only 不变式（自建探针当场抓到 UB）

- 时间：2026-11-14 23:40 (Asia/Shanghai)
- 任务：推进 M2.5 对抗面时自问「视图绑定能否重赋值」（borrowscope.rs 注释与 NllRegions 文档都假设 views are declare-only）。
