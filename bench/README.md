# 探索性基准

`python bench/run.py` 测试开发模式，`python bench/run.py --release` 测试优化模式，加 `--cold` 时每个 AE 构建使用全新空缓存（测量真实编译）。脚本使用本机 Python、Rust、GCC 和 Go。脚本先编译 AE 编译器，再分别编译三个求和程序，确认输出一致，记录每次构建/运行墙钟时间及可执行文件大小。运行过程使用系统临时目录，结果以 JSON 输出。

这只是验证测量流程，并非语言性能排名：输入很小；开发模式下 AE 使用 GCC `-O0`，Rust 使用 `opt-level=0`；优化模式分别使用 `-O2` 和 `opt-level=2`，Go 始终使用默认构建；相同数字的优化等级不代表优化完全等价。AE 的 `build` 复用内容寻址缓存：不带 `--cold` 时重复构建测的是缓存命中路径；冷构建请使用 `--cold`。各构建的外部工具链缓存状态不受控，运行时间包含启动开销，各组没有随机交错。Go 手动检查加法溢出，Rust 使用 checked_add，AE 启用内置检查；错误处理方式仍不同。没有测量 CPU 时间、峰值内存、缓存体积、Linux 或 Gojo。

后续必须加入相同优化目标、足够长且多样的工作负载、随机交错、CPU 时间和峰值内存、可重复的冷/热缓存定义及真实程序；记录完整环境和原始结果。运行输出可重定向到项目外部或自行选择的文件，避免把机器环境数据无意提交到仓库。

`python bench/phases.py` 将生成的 C 单独编译为目标文件，再单独链接，各运行五次并验证输出。该实验使用两次 GCC 调用，与正常一次调用的完整构建不完全等价；结果包含进程启动时间和不可控的缓存状态。
