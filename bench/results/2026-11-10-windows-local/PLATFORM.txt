Windows 本机（开发机）
记录时间：2026-11-10
系统：Windows 10.0.26300 x64（Git Bash / MinGW 环境）
GCC：gcc.exe (MinGW-W64 x86_64-ucrt-posix-seh, built by Brecht Sanders, r3) 16.2.0
Rust：rustc 1.99.1 (58cf8f9c3 2026-10-13)
Go：go1.26.0 windows/amd64
Python：3.10.11
重跑：python bench/run.py [--release] [--cold] [--workload sum|text|all]

文件说明：
- bench-dev.json      开发模式（AE -O0 / Rust opt-level=0），缓存默认（含命中路径）
- bench-rel.json      优化模式（AE -O2 / Rust opt-level=2）
- bench-cold.json     冷缓存模式（--cold，每轮全新 AE_CACHE，测量真实编译）

两个工作负载：
- sum   一百万次带溢出检查的加法（ae / go / rust）
- text  读取 2,588,890 字节的 5 万行文本，按空格切分，输出字节数、令牌数、令牌内字节和
        （ae / go / rust / python；Python 无构建阶段，运行时间含解释器启动）

结果摘要（中位数，5 次；ms；峰值内存为直接子进程工作集高水位）：

sum
- 开发热缓存：ae 构建 74.7 / go 1344.0 / rust 300.8；运行 48.1 / 125.1 / 150.4
- 优化：ae 构建 73.2 / go 1261.9 / rust 244.5；运行 41.2 / 111.5 / 70.5
        运行峰值 9.10 / 10.89 / 9.16 MB；产物 61,429 / 2,460,160 / 131,072 字节
- 冷缓存：ae 构建 1234.4 / go 1284.1 / rust 247.2

text
- 优化：ae 构建 78.7 / go 1398.0 / rust 314.8；运行 86.1 / 172.8 / 72.5，python 288.2
        运行峰值 23.91 / 23.56 / 10.75，python 51.11 MB
        产物 67,012 / 2,639,872 / 151,552 字节，python 脚本 629 字节
- 冷缓存：ae 构建 1211.0 / go 1335.7 / rust 270.2

观察（仅此机器、此输入）：
1. 热缓存下的 AE 构建时间主要由缓存命中决定（约 75ms），不能当作编译速度证据。
2. 冷构建约 1.2s 中绝大部分是 GCC 编译约 1MB 生成 C 的时间，已接近 Go 的整个构建；
   这是阶段 D 要用「更小生成 C / 增量 / 自有后端」解决的第一个可量化目标。
3. text 负载下 AE 运行峰值 23.9MB 明显高于 Rust 的 10.8MB：split 为每个令牌分配
   一个独立字符串（40 万个），每次分配都带 malloc 头部与 16 字节对齐的代价。这是
   「数据结构空间成本公开」的第一个真实数据点，也是后续引入零拷贝切片/区域分配的依据。
4. 编译产物 67KB 对 152KB/2.6MB，符合「低磁盘占用」目标；Python 脚本 629 字节但依赖解释器。

注意事项：这是单机探索性测量，输入很小，除 --cold 外缓存状态不受控，温度与电源策略未记录，
不构成语言性能结论。
