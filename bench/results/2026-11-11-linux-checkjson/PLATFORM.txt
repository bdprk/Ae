## 命令（工作目录 = ~/ae-lang）
- cargo build --locked && cargo test --locked
- python3 scripts/verify_generated_c.py --leak
- python3 scripts/verify_generated_c.py --sanitize
- for f in examples/*.ae; do target/debug/ae check "$f"; done
- target/debug/ae check --json <good.ae> / <bad.ae> / <missing> / 参数顺序颠倒
- target/debug/ae check <bad.ae>（默认单行输出对照）
- target/debug/ae emit-c <print(1) 探针> | wc -c

- --leak：27 个用例 PASS，退出分配块 0（glibc 基线）；--sanitize：27 个用例 PASS，0 报告。
- 全部 34 个 examples 通过 check（0 个失败）。
- check --json 输出与 Windows 同形状，路径为 `/tmp/...`（无转义需要）。
- print(1) 生成 C 24,034 字节（与 Windows 相同）。

## 首轮暴露并修复的问题
集成测试最初无条件断言路径含反斜杠转义，Linux 上必然失败（路径分隔符是 `/`）。
修正为 `#[cfg(windows)]` 断言转义、`#[cfg(unix)]` 断言绝对路径后两平台全绿。
教训：断言输入形状的平台差异必须用 cfg 分开，不能把 Windows 的形状当通用事实。
