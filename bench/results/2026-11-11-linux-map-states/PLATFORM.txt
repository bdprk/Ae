ADR-57 map 状态位搬出槽（32 → 24 字节）· Linux 归档（2026-11-11）

## 平台
instabox-node 沙箱：Debian 13，x86-64，4 vCPU；gcc 14.2.0-19；rustc 1.99.0；go 1.27.1。
对照二进制在 `~/mapprobe`：`-v2` = ADR-56 的 32 字节槽，`-v5` = 本轮的 24 字节槽 + 状态数组，
`-rs`/`-go` 为同源孪生程序。

## 改动
`unsigned char state` 从 `ae_map_slot` 里搬出，改为平行的 `unsigned char *states`（每槽 1 字节）。
槽只剩 `{ ae_string key; int64_t value; }` = 24 字节（原来 32），表本体 32768 × 32 = 1,048,576
字节 → 32768 × 25 = 819,200 字节。`find/put/inc/remove/grow/release/forfeit` 与 `keys` 全部改走状态数组；
探测链先读 32 KB 的状态数组（常驻 L1/L2），只有 FULL 时才碰 24 字节的槽。

## 命令（工作目录 = ~/ae-lang）
- cargo build --release --locked && cargo test --locked
- python3 scripts/verify_generated_c.py --leak / --sanitize
- for f in examples/*.ae; do target/debug/ae check "$f"; done
- python3 bench/run.py --release > suite-release.json
- cd ~/mapprobe && python3 pair.py map-v2 map-v5（11 次交替、配对比值）
- cd ~/mapprobe && python3 measure.py map-v2（7 次，VmHWM 单独一趟采样）

## 结果
- cargo test：35 单元 + 164 集成全通过。
- --leak 30 用例 PASS、退出块 0；--sanitize 30 用例 PASS、0 报告；37 examples check 全过。
- 配对测量（11 次交替，比值逐对计算）：
  - map 负载 59.84 → 59.36 ms（**1.012×**，持平）
  - hit 探针 51.14 → 50.98 ms（1.007×）
  - put 探针 49.11 → 47.53 ms（1.027×）
- 峰值内存（VmHWM，7 轮取最大）：**3.43 → 2.90 MB（−15%）**；Rust 3.04、Go 7.77。
  表本体 −22%，峰值只降 15%，因为 1M 次键字符串分配占了大头。
- 四负载套件（release，5 次交错）：sum 0.92 / text 10.37 / textlazy 3.87 /
  **map 59.88 ms、峰值 2.86 MB**（Rust 56.99 / 2.91、Go 69.71 / 7.49、Python 245.64 / 9.36）。
  时间仍落后 Rust 约 5%，**内存已低于 Rust**。

## 边界
内部布局改动：`keys()` 仍按字节序排序、哈希未改、可观察行为不变。
时间是「持平」不是「更快」——`put` 的 1.027× 多数比值 >1，map 负载的比值一半在 1 附近，属噪声边缘。
