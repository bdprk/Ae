ADR-60 数学内建（sqrt/abs/floor/ceil/round/exp/log/sin/cos/pow/atan2）· Windows 归档（2026-11-11）

## 平台
Windows x86-64，8 核 / 16 线程，MinGW-W64 GCC 16.2.0（UCRT）。AE 0.1.1。

## 命令（工作目录 = 仓库根）
- cargo test --locked
- python scripts/verify_generated_c.py --leak（用例表新增 math_basics.ae，POSIX 编译行加 -lm）
- python scripts/fmt_acceptance.py --json fmt-acceptance.json
- for f in $(find examples -name "*.ae" ! -name "report.ae" ! -name "words.ae"); do ae check "$f"; done
- cargo run -- run examples/math_basics.ae（精确值输出与容差检查，见下）

## 结果
- cargo test：35 单元 + 170 集成全通过。新增 3 个集成测试：
  `math_builtins_compute_report_domain_errors`（11 个内建的精确值 + `sqrt(-1)`→`nan`
  + `to_string` 读回判断）、`math_transcendental_values_land_within_a_tolerance`
  （sin(1)/cos(1)/atan2(1,1)/sqrt(2)/log(exp(1))/pow(2,0.5) 以 1e-15 容差判定）、
  `math_builtins_reject_wrong_types_arities_and_redefinition`（i64/bool 实参、
  元数过多过少、函数重定义、变量重名全部被拒绝）。
- --leak：32 个用例 PASS（原 31 + math_basics），退出分配块数全部等于 UCRT
  基线 2 块——数学内建不分配内存，`nan` 读回与拼接不残留块。
- fmt 验收：42 个文件全部通过（基线 emit-c → fmt → 生成 C 逐行数字无关比较 →
  二次 fmt 逐字节幂等），math_basics.ae 已是格式化形态（changed: 0）。
- 40 个程序通过 `check`（新增 math_basics.ae；report.ae/words.ae 是库模块，
  被正确拒绝计入行为）。
- `examples/math_basics.ae` 运行输出（Windows 实测）：
  sqrt(4) 2.0 / abs(-2.5) 2.5 / floor(2.7) 2.0 / ceil(2.1) 3.0 /
  round(2.5) 3.0 / round(-2.5) -3.0 / pow(2,10) 1024.0 / exp(0) 1.0 /
  log(1) 0.0 / sin(0) 0.0 / cos(0) 1.0 / sqrt(-1) nan，随后 6 个容差检查全部 ok。

## 资源成本
- 生成 C：`print(1)` 保持 13,822 字节（MATH_FNS 是编译器端的常量表，
  不进生成 C；数学内建直接调用 libm 符号，无运行时函数、无裁剪根）；
  math_basics.ae 为 25,044 字节（其中大部分是字符串拼接簇，与数学无关）。
- 链接行：Linux 加 `-lm`（glibc 2.35+ 为合并后的空壳，旧 glibc 必需）；
  Windows 不变（符号在 C 运行时里）。这是链接命令变化，已把 Cargo.toml
  版本提升到 0.1.1 使全部内容寻址缓存条目失效——缓存键含编译器版本。
- `sqrt(4)`→`2.0` 等精确值跨平台一致的前提是结果值一致（sqrt 按 IEEE 正确
  舍入、floor/ceil/round/exp(0)/log(1)/sin(0)/cos(0) 精确、pow(2,10) 在两个
  libm 中都是精确整值）；文本由运行时自产，不依赖 CRT printf。

## 说明
- 过程发现：fmt_acceptance 第一次失败（`unknown function 'abs'`）不是 fmt 的
  问题——脚本用的是 `target/release` 的旧二进制（构建于数学库之前），重建后
  42 个文件全部通过。教训照旧：验证脚本对「刚改完前端」的时刻敏感，跑验收
  前先确认 release 二进制与源码同步。
- 附带修复：`cache_and_version_commands_work` 硬编码了 `ae 0.1.0`，
  版本提升使它失败；改为跟随 `CARGO_PKG_VERSION`，以后提升版本不再破测试。
- Linux 回填待做：同一提交树在 Linux 原生跑全套（`--sanitize` + `--leak` +
  fmt 验收 + 示例输出行尾归一化比较），归档 `2026-11-11-linux-math/`，
  状态才升级为双平台验证；届时同时确认 glibc 的 pow(2,10)=1024 精确值。
