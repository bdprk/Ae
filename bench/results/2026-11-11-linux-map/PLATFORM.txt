## 观察（只报方向与量级，不作排名）
1. 运行时间：release 下 ae 82 ms 落在 Go 70 ms 与 Rust 58 ms 之间
   （≈1.17×Go、≈1.42×Rust）；dev 下 ae 133 ms 快于 Rust dev 178 ms。
   方向与 Windows 归档一致：ae 的 map 路径慢于两参照，热点未定位。
2. 运行峰值内存：ae 2.37 MB < Rust 3.00 MB < Go 7.19 MB < Python 9.31 MB。
   与 Windows 归档同方向（ae ≈ Rust、明显低于 Go），且两平台 ae
   峰值都最低——map 路径的内存表现是两条负载里最好的一条。
3. 冷构建 56–136 ms 是该小程序在本机的真实全流程时间（含 gcc 与链接）；
   热缓存 build_med 3.8–4.6 ms 是命中路径，不作编译速度证据（§20.4 第 5 条）。
4. 产物体积：ae 22.3 KB < Rust 4.56 MB ≈ Go 2.35 MB（release，Linux ELF）。

## 已知差异 / 归一化规则
- CPU 时间本平台有值（resource.getrusage，直接子进程），见 JSON。
- 构建峰值只含直接子进程驱动；gcc 的 cc1/as/ld 不计入。
- 输出比较先做行尾归一化；本归档四轮输出原始一致。
- 与 Windows 归档跨机不比绝对时间；只比方向与相对关系。
