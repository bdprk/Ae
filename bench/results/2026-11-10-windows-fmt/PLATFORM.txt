## 语义不变的精确表述（不得越线）
不宣称 emit-c 逐字节相同：运行时检查在生成 C 里嵌入源码列号，重排空格
移动列号；行号不变（行结构逐行保留）。验收性质 =
(a) token 序列、每 token 行号、注释/字符串/字面量字节不变（fmt 契约 +
    词法器等价单测，35 文件）；
(b) 格式化前后 emit-c 在「每行忽略数字字符」的归一化下逐行一致
    （脚本断言，任何其他差异即失败）；
(c) 格式化后的程序运行输出一致（集成测试断言）。

## 设计要点（详见 ADR-42）
- 有效性门槛 = 可被编译器词法器切分，不要求完整检查：模块文件没有 main，
  无法独立整程序检查；语义错误不影响空白重排的安全性。
- 幂等由构造成立：间距只依赖相邻 token 类对，缩进只依赖花括号深度，
  换行与空行数量、尾注释对齐空隙原样保留。
- 开发中被语料抓出并修正的规则 bug：`var v =[10, 20, 30]`（`[` 规则误伤
  数组字面量）、`=> { }`（空块插入空格）、`if ! seed(`（`!` 未判为前缀）。
  教训：间距规则必须对全部示例 diff 逐条核对；幂等断言对错误规则同样成立，
  抓不住风格错误。

## 已知差异 / 未覆盖
- Linux 回填未做：当前状态为「单平台验证」（§22.2），不写「双平台验证」。
- fmt 不重排行结构（长行不拆不并排）、不重对齐尾注释（只保留原空隙）、
  不折叠连续空行——v1 明确取舍，非遗漏。
- fmt 不做完整检查，因此不构成「文件有效」的信号；`check` 仍是唯一语义门槛。
- 生成 C、运行时、缓存完全未被 fmt 触碰；本轮无新增 C 路径需要净化器复跑
  （全部既有 C 执行测试在 145 集成内原样通过）。
