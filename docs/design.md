# AE 设计与路线

## 自主研发与参考

语言规范、前端、类型与安全检查、IR、运行时和标准库由本项目自主设计编写。可研究公开设计，但不复制 Gojo 的实现。Gojo 是实验性系统语言，当前仓库描述其使用所有权、生成 C，且尚不支持 Windows；它是参考和 Linux 上的对比基线，不是 AE 的功能规格。Rust、C 编译器、链接器与系统 API 属于允许使用的基础设施。参考：https://github.com/egoist/gojo

## 安全目标

安全代码预期防止越界、悬空引用、释放后使用、重复释放与数据竞争。当前原型没有动态内存与并发，不能据此宣称已实现这些保证。未来需先定义所有权、借用、整数与错误语义，再实现检查、对抗性测试及跨平台验证。unsafe 与 FFI 另设明确边界。

## 顺序

1. 固定两平台工具链和基准方法，收集 Go、Rust 和 Linux 上 Gojo 的基线。
2. 完善词法、源位置、语法树、变量、类型和明确的整数行为。
3. 建立中间表示、控制流、所有权与受限借用检查，以及资源释放规则。
4. 实现文件、字符串、数组及两个平台的适配，完成文件搜索工具。
5. 建立阶段计时、增量构建和缓存限额，按实测分析 C 后端瓶颈。
6. 扩充安全和模糊测试，发布可复现的 CPU、内存、磁盘与构建报告，再决定后端升级。

每个阶段须同时验证 Windows 和 Linux；Gojo 尚不支持 Windows，Windows 对比标记为不可用。对比需等功能、固定版本和相同输入，记录安全检查、构建配置和原始数据。
