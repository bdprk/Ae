# ADR-63：通用借用检查器设计稿（阶段 C 核心，状态：已设计，未实现）

- 背景：当前借用是「块作用域只读 + 变量 id 粒度 + 不可逃逸」（resource-model.md §4）。它安全但表达力受限：字段粒度不存在（ADR-52 的已知边界）、借用不能返回或存储、泛型借用在循环里的存活粒度是整块。§21 把「通用借用检查器设计」列为首要候选；本轮交付**设计**，不动实现。
- 交付：`docs/borrow-checker-design.md`——目标模型（Loan/Place/Origin、Shared 先行 Mut 后置、有序约束替代生命周期标注、「两可来源即拒绝」的取舍）、表达力阶梯 L0–L5（每级独立验收，NLL → 字段粒度 → 逃逸 → 元素借用 → 可变借用）、释放交互（借用活跃不释放、无引用计数、借用安全完全前移编译期）、**10 类对抗性用例矩阵**（实现前先写测试）、推进顺序与验收门槛（放宽必须带差分基线）。
- 关键设计决定：
  1. **两可来源即拒绝**：`fn longer(a: &string, b: &string) -> &string` 这类需要「选一个来源」的函数直接拒绝（用户返回拥有值），而不是引入生命周期标注——用户永不标注是目标，代价是拒绝这一类函数；这是明确的取舍，不是遗漏。
  2. **借用安全完全前移到编译期**：逃逸借用的宿主释放必须编译期证明无活跃 loan，运行时不加哨兵；moved 哨兵保留在所有权路径上不动。
  3. **循环固定点不收敛即拒绝**（带上限与指认哪条借用），不做「猜一个最短的」。
  4. 每级放宽必须逐条点名现有拒绝集中哪些变成放行并给出安全论证——「实现变宽松了」本身不是放行理由。
- 边界（对外表述不得越过）：
  - **不宣称借用检查器已升级**：当前实现与本文描述的 L0 一致；L1–L5 全部未实现，本文是设计稿。
  - 不承诺「永远无需生命周期标注」：设计目标是如此，若 L3 实现证明需要标注，另立 ADR 讨论而不是悄悄加。
  - 不给时间表；每级一个 ADR + 差分基线 + 双平台。
- 验证：纯设计交付，无可运行证据；验收方式是文档评审——与 resource-model.md §4（现状）、ADR-35/52/61（已有能力）、§20.4 第 1 条（放宽纪律）逐条核对一致，`resource-model.md` §10 已建立指针。实现阶段按 §6 推进，每级单独验收。
