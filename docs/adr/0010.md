# ADR-10：枚举用「标签 + 每变体独立负载结构体」的联合，match 强制穷尽

- 背景：方案阶段 B 要求引入枚举与模式匹配；同时 §4.5 要求可恢复错误用结果值表达，而当前 `read_file` 失败只能终止进程。没有枚举就无法在语言内定义 `Result`/`Option` 式的可恢复错误。
- 决策：
  1. `enum Name { Variant, Variant(i64), Variant(string, bool) }`：变体可带 0–16 个位置负载，负载类型在首版限定为 `i64`/`bool`/`string`。构造写作 `Name::Variant(...)`。
  2. 布局为 C 的 `enum tag` + `union`，**联合的成员是每个变体各自的负载结构体**（`struct { int64_t p0; int64_t p1; }`），访问路径 `v.u.v1.p0`。
  3. `match 裸枚举变量 { ... }` 是语句；每个变体必须恰好出现一次（穷尽性），不提供通配符与嵌套模式。
  4. 枚举是拥有型值：赋值/传参/返回移动它，作用域退出、提前返回与跳转路径按变体释放负载；`release` 幂等，`forfeit` 只清空不释放。
  5. `string` 负载在分支里绑定为**只读视图**（`string view`），任何负载都不能被移出枚举；绑定变量不是拥有型，不参与释放。
  6. 编译期把 `match` 视为「全部变体都返回」才能满足返回值检查。
- 理由：负载结构体联合避免了 C 联合的字段别名问题；裸变量主题使借用跟踪器能保证「匹配期间主题不可移动/不可赋值」，无需跨语句临时值的生命周期分析；穷尽性检查让 `match` 没有漏网路径，也不需要运行时 trap。
- 已排除的做法：
  - **联合直接放各变体的字段**：C 的联合同一时刻只有一个成员有效，`{ .f1_0 = 4, .f1_1 = 5 }` 会互相覆盖。实测 `Rect(4,5)` 得到 `5x5`，故改为变体结构体。
  - **用 C `switch` 生成 match**：分支体里的 `break` 会被 `switch` 吞掉，破坏「break 退出最内层循环」的语义；改为 if/else 链，比较次数由编译器处理。
  - **允许 `vec`/结构体负载**：这些类型没有可绑定的借用表示（string 有 `string view`），移出又违反「不拆解拥有值」的一致规则；等视图类型扩展后再放开。
  - **`match` 作为表达式**：需要表达式级类型统一与临时值生命周期规则，先做语句形式。
- 后果与限制：`match` 主题必须是裸枚举变量（函数返回值需先绑定变量）；`enum` 与 `struct` 一样只支持同文件内先声明后使用；枚举值没有运行时空哨兵，移动后使用依赖编译期移动集合（与结构体一致）；负载不能嵌套枚举，因此不存在递归布局。
