# ADR-3: `string` as the First Owned Type; Move Semantics First

- **Context**: Deterministic resource management is required without a GC; the borrow checker needs to verify rules on a single type first.
- **Decision**: `string` owns a heap buffer; initialization/passing/assignment/returning triggers a move; `+` consumes both operands; `print`/`len` borrow. Use-after-move is rejected at compile time (via conservative union of branches); moving sets the pointer to NULL, with a pre-read null check as a runtime fallback; deallocation is idempotent, covering all paths including block exit, early return, `break`/`continue`, and `return`.
- **Rationale**: Establish end-to-end correctness of the ownership mechanism on a restricted grammar before generalizing to structs/containers; the runtime fallback ensures that "even if the analyzer has a bug, it is not a memory error."
- **Consequences**: "Use-after-move" inside a loop body can only be caught by runtime checks (compile-time conservative union already covers post-loop usage); high-frequency string operations incur copy overhead. If runtime checks become a hotspot, they should be eliminated based on position once safety is proven.
