# ADR-30：泛型结构体用与泛型枚举相同的单态化

- 背景：泛型枚举（ADR-21）解决的是「一个值可能是 A 也可能是 B」，但数据的**成对/成组**关系仍然只能靠并列变量或平行向量表达。`Pair[K, V]`、`Map.Entry` 这类结构在一门系统语言里无法回避，而当时 `struct P[T]` 会在解析处直接报「不支持」。同时，泛型结构体是通往 `Result[T, E]` 与泛型函数的第一步：先证明单态化在「有布局、有释放」的类型上也成立，再把它用到有函数体的地方。
- 决策：
  1. `struct Name[T, U] { ... }` 与泛型枚举共用类型参数规则（单个大写字母、最多 8 个、不得重复），也共用「声明不产生布局」的原则：只有 `Name[string, i64]` 这样的**实例化**才产生 `typedef`。
  2. 实例化键是「声明 + 实参列表」，与 `instantiate_struct` 的 `struct_done` 缓存一致：同一实参列表复用同一个 `StructDef`（也就复用同一个 `ae_tN` 与 release/forfeit），因此同实参的值可以互相赋值、可以共用同一个参数类型。
  3. 类型实参用 `named_type()` 解析，比泛型枚举的 `type_argument()`（扁平类型）更宽：结构体、枚举、已实例化的泛型都能当实参。理由是结构体字段本来就能容纳结构体与枚举，放宽不会引入新的布局形状；枚举负载仍然限扁平类型，因为枚举的负载结构必须能按变体 `free`。
  4. 字段类型在声明期用 `Payload`（`Concrete`/`Param`）表示，实例化时替换成实参，与枚举变体负载同一套机制，`Param` 不会漏到代码生成。
  5. 预算：`MAX_STRUCT_TYPES = 256`（含普通结构体），与枚举的 256 分开计，超限在实例化处报错。
- 理由：不引入「泛型结构体的运行时代码」——单态化后它就是普通结构体，释放、字段借用、移动检查全部沿用既有实现，因此不需要新的运行时设施，也不会让「结构体字段不能移出」这条安全规则出现例外。允许结构体/枚举做实参，是因为限制实参种类省不下多少实现，却会让 `Pair[i64, Tag]` 这种最自然的写法无法表达。
- 顺带修复一处缺陷：`skip_struct_def` 只跳过 `struct Name` 再接 `{`，遇到 `[T]` 就把 `[` 当成左花括号，然后一路跳到文件末尾，`fn main` 被静默吞掉，报错却是「found 0 main function」。现在与 `skip_enum_def` 一样先调用 `skip_type_params()`；这个缺陷是加泛型时被最小用例暴露的，说明两个跳读函数必须同形。
- 已排除的做法：
  - **让泛型结构体的字段可以是 `T` 的向量（`vec[T]`）**：`vec` 的元素类型是编译期固定的 `i64` 或 `string`，要做通用容器得先有元素类型描述符，属于另一件事。
  - **trait/约束（`T: Printable`）**：没有 trait 与静态分派之前，约束只能是个空承诺；先让单态化跑通，再把约束设计成「对实参形状的检查」。
  - **在类型位置省略实参并做推断**：语言目前没有任何类型推断，省略实参会让 `Pair { left: "a", right: 1 }` 需要从字段表达式反推实参，那是另一套机制。
- 后果与限制：实例化只发生在**使用处**，因此错误位置指向使用处而不是声明处；错误信息里的结构体类型仍显示为 `struct #N` 而不是 `Pair[string, i64]`（`Type::Struct` 只带 id，未像 `Type::Enum` 那样带名字，后续可对齐）；`&Pair[string, i64]` 借用参数暂不支持（`&` 只接受 `string`/`vec`/数组），大结构体只能按值传；泛型函数仍未实现。新增 `examples/pairs.ae`、1 个端到端测试（含 8 个必须被拒绝的写法），并把 `pairs.ae` 加入生成 C 校验的分配计数用例。
