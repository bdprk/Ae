# ADR-5: Bounds of `for` Range Loops Are Evaluated Once, Counter Is Immutable

- Context: The semantics of `for i in a..b` must be unambiguous (Proposal §4.2 Evaluation Order).
- Decision: Bounds are evaluated once from left to right and stored in hidden variables; `i` is an immutable `i64` within the loop scope; the implicit increment uses checked arithmetic; `continue` jumps to the increment (generating a label), whereas `continue` in `while` loops retains C semantics.
- Rationale: Consistent with common languages and predictable; reuses checked arithmetic to prevent silent overflow wrapping.
- Consequences: Modifying bounds inside the loop does not affect the iteration count (use `while` when dynamic bounds are needed); labels make the generated C code slightly harder to read, which is an acceptable cost.
