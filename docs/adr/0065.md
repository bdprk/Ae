# ADR-65：`map[string, f64]`——第二 map 形状与预置枚举 `FloatResult`

- 背景：`vec[f64]`（ADR-61）落地后，f64 数据分析栈缺的最后一块容器是哈希表（传感器最新值表、特征权重表）。map 的形状决定比向量难一处：`map_get` 返回 `IntResult`（缺失返回理由文本），f64 版需要自己的结果形状——这就是本轮的核心设计决定。
- 决策：
  1. **预置枚举 `FloatResult{Ok(f64), Err(string)}`**，与 `IntResult` 对称：缺失返回共享的只读 `"key not found"`（ADR-58 常量，未命中零分配），错误处理语义两族一致。备选 `Option[f64]`（None 无文本）被否——错误文本哲学（§4.5「I/O 接口不能静默丢弃错误」）在 map 族已经确立，两种 map 的读取形状不一致会让调用方写出两套风格。
  2. **追加在 prelude 末尾**：既有 8 个枚举的 id 全部不变（payload id 是位置性的，插队会改写所有既有生成 C）；运行时以 `ae_e8`/`AE_FLOAT_*` 宏引用，prelude 顺序断言保持首位 6 个不变、新增第 9 位。
  3. **MapPlace 携带 MapKind**：六个 map 内建（get/has/remove/inc/keys/索引写）共用一个 place 结构，按 `f64_value()` 分派 C 符号——比给六个 Expr/Statement 变体各加字段少一半改动，解析点从变量类型推断 kind。
  4. **运行时家族与 i64 map 同构**：24 字节槽（键 16 + double 8）、并行状态字节、半装载扩容（ADR-56/57 的结论直接继承）；哈希与槽位计算**复用** i64 版函数（只依赖键，与值类型无关），不复制。
  5. **`map_get` 缺失语义与索引读不存在**：`m[key]` 作表达式不编译（本轮在示例里再次确认这条既有规则）——读取必须走 Result 形状，「缺失」与「值」不可混淆。
- 已排除的做法：
  - **`Option[f64]` 作为 map_get 返回**：见决策 1；两个 map 族的错误形状必须一致。
  - **把 map 泛型化**（`map[K, V]`）：与 ADR-61 同理，泛型容器是独立决策。
  - **mapf 的哈希/槽位计算复制一份**：键侧逻辑与值类型无关，复制只会让 ADR-56/57 的调优结论失同步。
  - **按需布局（只发被引用的 prelude 枚举布局）**：能把 +911 字节的常驻前缀拿回来，但它改动 W3 确立的「前缀逐字节相同」不变量，值得单独立项（记为候选），不塞进本轮。
- 资源成本（归档 `bench/results/2026-11-12-windows-mapf/`）：
  - **生成 C**：`print(1)` 13,909 → 14,820（+911 = 第 9 个 prelude 枚举的布局与 release/forfeit 进常驻前缀；mapf 函数未引用即裁剪，print(1) 中 0 个保留）。二进制无影响（未引用枚举不产生代码）。这是「新增 prelude 枚举」的固定代价，如实记录。
  - **运行时**：槽 24 字节/条目，与 i64 map 相同；`--leak` 34 用例（新增 sensor_stats）基线不变——扩容、tombstone、字段释放恰好一次。
  - **验证**：36 单元 + 179 集成（新增 3 个）、fmt 44 文件、42 程序 `check`。
- 边界（对外表述不得越过）：
  - 不宣称「泛型 map」：两个手写家族，`map[string, f64]` 不派生第三、第四个值类型——再+1 前应先评估泛型化或按需布局。
  - 不宣称「+911 字节无所谓」：它是所有程序的常驻文本成本；按需布局是明确的后续候选，记录在案。
  - 枚举 `==` 仍不存在：map_get 的结果必须 match（拒绝用例覆盖）。
  - 键仍只有 string；int 键不在本轮。
- 过程发现：
  1. **map 索引读不存在**（有意设计）再次确认——示例初版直接踩到，改走 map_get + match。
  2. **字段 map 赋值的外层类型检查漏改**（`fty == Type::Map` 没带 MapF）：变量分支改了、字段分支没改——与 ADR-61 的 by_ref 教训同类，「同一规则的第二处出现」必须 grep 全部出现点。
  3. heredoc→python 转义第三次出错后，本轮全部改为 Write 落盘脚本 + 原始字符串，未再发生——硬规则生效。
- 验证：Windows 36 单元 + 179 集成、`--leak` 34 用例 PASS（基线 2 块）、fmt 44 文件、42 程序 `check`；归档 `bench/results/2026-11-12-windows-mapf/`。Linux 回填（同一源码树 740b50c，`bench/results/2026-11-12-linux-mapf/`）：36 + 179 全通过、`--leak` 34 用例基线 0 块、`--sanitize` 34 用例 0 报告、fmt 44 文件幂等、**sensor_stats 输出两平台逐字节一致**、生成 C 字节数两平台相同（print(1) 14,820）。状态：**双平台验证**（2026-11-12）。
