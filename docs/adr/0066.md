# ADR-66：prelude 枚举布局按需发出——小程序不再背负用不到的结果类型

- 背景：ADR-65 追加第 9 个 prelude 枚举（FloatResult）后量到 `print(1)` 生成 C +911。复盘发现真正的问题不是「多了一个枚举」，而是**所有** prelude 布局自 W3 起就无条件常驻——`print(1)` 一直背着 8 个用不到的布局。本轮把布局改成按需，把 ADR-65 的代价连同历史欠账一起拿回。
- 决策：
  1. **布局存在当且仅当被引用**：用户代码命名 `ae_eN`（声明/release/forfeit 调用），或被保留的运行时函数体使用该枚举的 `AE_<NAME>_` 宏族。两条覆盖全部使用形态：宏是运行时代码引用 prelude 类型的唯一方式，用户代码只写小写 `ae_eN`。
  2. **`#define` 行从根符号收集中排除**：此前 ex 顶部的 `#define AE_FLOAT_RESULT ae_e8` 是无名单元，其体内的 `ae_e8` 会被根扫描当作引用 → 布局全保留，优化失效。排除的依据是审计过的性质：44 个 #define 体全部是数字或类型名，**没有函数调用**；宏的「使用」由保留函数体扫描兜住。这条审计写成了注释，新增带函数体的 #define 时必须重新审视。
  3. **release/forfeit 仍是普通命名单元**：参与可达闭包，被调用才保留；typedef 在闭包后按 `ae_eN` 是否入 keep 集决定。三片（typedef/release/forfeit）独立发射，枚举被用但 release 无调用方时只发 typedef。
  4. **`prune_runtime` 改为三段输入**（core / ex / 布局片）：布局单元插在 core 与 ex 之间参与同一个闭包，输出按 core → 需要的布局 → ex 装配——typedef 先于 runtime_ex.c 文本的顺序不变（ex 的函数签名引用这些类型）。
- 已排除的做法：
  - **保持常驻 + 接受 +911**：`print(1)` 是「空程序」的代理指标，它背 9 个未用布局说明机制错了，不是成本可接受的问题。
  - **把 prelude 枚举搬进用户枚举区**（统一按需）：prelude 枚举的 payload id 被 8 个结果内建的生成 C 硬引用（AE_INT_RESULT = ae_e2），搬动即改写所有既有生成 C；按需发射不动 id。
  - **让 #define 行参与根扫描但排除 ae_eN**：特例越堆越多；「#define 体不是根」是比「排除特定符号」更清晰的规则。
- 资源成本（归档 `bench/results/2026-11-12-windows-demandlayouts/`）：
  - **生成 C**：`print(1)` 14,820 → **12,733**（−2,087；比 ADR-65 之前的 13,909 还低 1,176——历史欠账一并清偿）；float_stats 31,607（−1,176）；sensor_stats 39,964（−1,778，只留 FloatResult）。
  - **验证**：36 单元 + 179 集成、`--leak` 34 用例基线不变、fmt 44 文件、42 程序 `check`。
  - **编译器**：prune_runtime 签名变化 + prelude_enum_pieces 拆分；无新的运行时函数。
- 边界（对外表述不得越过）：
  - W3 的「运行时前缀逐字节相同」性质**由此改变**：runtime.c 段仍逐字节相同，中段（布局）随程序变化。原性质支撑的「编译产物跨程序复用」从未实现（分离 TU 已被 ADR-38 否决回退），新不变量以本 ADR 为准。
  - 生成 C 字节数继续「随所用内建变化」（ADR-38 边界重申），且现在也随所用**结果枚举**变化——外部工具不得再假设任何固定字节数。
  - 布局缺失的失败模式是 C 编译期显式报错（未定义类型），不是静默行为变化。
- 过程发现：重构脚本的第一版把「删除陈旧 runtime_len 行」写成独立步骤，但那行已被头段替换一并消费——批量重构前先在脑中跑一遍每步之后的文本状态，锚点会移动。
- 验证：Windows 36 单元 + 179 集成、`--leak` 34 用例 PASS（基线 2 块）、fmt 44 文件、42 程序 `check`；归档 `bench/results/2026-11-12-windows-demandlayouts/`。Linux 回填（同一源码树 344a31a，`bench/results/2026-11-12-linux-demandlayouts/`）：36 + 179 全通过、`--leak` 34 用例基线 0 块、`--sanitize` 34 用例 0 报告、fmt 44 文件幂等、**print(1) 生成 C 12,733 两平台完全相同**（裁剪判定是确定性文本计算）。状态：**双平台验证**（2026-11-12）。
