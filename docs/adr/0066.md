# ADR-66: On-Demand Emission of Prelude Enum Layouts — Small Programs No Longer Carry Unused Result Types

- Background: After appending the 9th prelude enum (`FloatResult`) in ADR-65, the generated C size for `print(1)` increased by +911 bytes. A retrospective revealed that the real issue wasn't "an extra enum," but rather that **all** prelude layouts had been unconditionally resident since W3—meaning `print(1)` had always been carrying 8 unused layouts. This iteration changes layouts to be on-demand, reclaiming the cost of ADR-65 along with all historical technical debt.
- Decision:
  1. **A layout exists if and only if it is referenced**: Referenced either by user code naming `ae_eN` (declaration/release/forfeit calls), or by retained runtime function bodies using the enum's `AE_<NAME>_` macro family. These two cover all usage forms: macros are the only way runtime code references prelude types, while user code only writes lowercase `ae_eN`.
  2. **Exclude `#define` lines from root symbol collection**: Previously, the `#define AE_FLOAT_RESULT ae_e8` at the top of `ex` was an unnamed unit, and the `ae_e8` within its body would be treated as a reference by the root scanner → all layouts were retained, disabling the optimization. The exclusion is based on an audited property: all 44 `#define` bodies consist solely of numbers or type names, with **no function calls**; the "usage" of macros is fully captured by the retention scan of function bodies. This audit has been documented as a comment, and adding any new `#define` with a function body requires re-evaluation.
  3. **`release`/`forfeit` remain regular named units**: They participate in the reachable closure and are retained only when called; typedefs are determined based on whether `ae_eN` is in the keep set after the closure. The three pieces (typedef/release/forfeit) are emitted independently; if an enum is used but `release` has no callers, only the typedef is emitted.
  4. **`prune_runtime` modified to accept three inputs** (core / ex / layout pieces): Layout units are inserted between core and ex to participate in the same closure, and the output is assembled in the order core → required layouts → ex. The ordering where typedefs precede `runtime_ex.c` text remains unchanged (as ex function signatures reference these types).
- Rejected Alternatives:
  - **Keep resident + accept +911**: `print(1)` is a proxy metric for an "empty program"; carrying 9 unused layouts indicates a flaw in the mechanism rather than an acceptable cost.
  - **Move prelude enums into the user enum region** (unified on-demand): Prelude enum payload IDs are hardcoded in the generated C of 8 result builtins (`AE_INT_RESULT = ae_e2`), so moving them would rewrite all existing generated C; emitting on-demand leaves IDs untouched.
  - **Let `#define` lines participate in root scanning but exclude `ae_eN`**: Accumulating special cases leads to complexity; establishing the rule that "#define bodies are not roots" is cleaner than "excluding specific symbols."
- Resource Costs (archived at `bench/results/2026-11-12-windows-demandlayouts/`):
  - **Generated C**: `print(1)` 14,820 → **12,733** bytes (−2,087; 1,176 lower even than the 13,909 prior to ADR-65—historical technical debt fully cleared); `float_stats` 31,607 (−1,176); `sensor_stats` 39,964 (−1,778, leaving only `FloatResult`).
  - **Verification**: 36 unit tests + 179 integration tests, `--leak` 34 test cases baseline unchanged, fmt 44 files, `check` on 42 programs.
  - **Compiler**: Signature change for `prune_runtime` + splitting of `prelude_enum_pieces`; no new runtime functions.
- Boundaries (external statements must not exceed):
  - The property from W3 stating "runtime prefix bytes are identical" **changes as a result of this**: the `runtime.c` segment remains byte-identical, but the middle segment (layouts) varies per program. The historical property supporting "compilation artifacts being reusable across programs" was never realized (separated TUs were rejected and rolled back by ADR-38); the new invariant is governed by this ADR.
  - The generated C byte count continues to "vary with used builtins" (reiterating the ADR-38 boundary), and now also varies with used **result enums**—external tools must no longer assume any fixed byte count.
  - The failure mode for missing layouts is an explicit C compile-time error (undefined type), not a silent behavioral change.
- Process Discovery: The first version of the refactoring script implemented "deleting obsolete `runtime_len` lines" as a separate step, but that line had already been consumed and replaced by the header section. Always mentally trace the text state after each step before batch refactoring, as anchor points will shift.
