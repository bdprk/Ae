# ADR-0226: R2.4 Remainder Is Blocked on Copy-Semantics Aggregates and First-Class Function Values

- Status: Accepted (blocking record; no language change in this slice)
- Date: 2026-11-21
- Associated Milestone: R2.4 (ADR-0224 realignment track)

## Context

ADR-0224 R2.4 asks for `cancel_*`, `pool_*`, `exec_*`, `timer_*` and
`shared_*` to leave the compiler and become ae source over the `keep`
primitives (atomics, mutex, channel, scope). R2.4a retired `cancel_*` and
`timer_*` because both reduce to one `atomic` cell plus ordinary arithmetic
(`std/sync/cancel.ae`, `std/task/timer.ae`).

The remaining families do not reduce the same way. Each one needs a shape the
language cannot express today, and the experiments below show which shape.

## Experiments

All commands run against `target/debug/ae` built from this revision; the
programs are the ones quoted inline.

| Needed shape | Probe | Observed |
|---|---|---|
| A copy-semantics user aggregate (a shared box handle must be copyable, because `spawn` moves value captures and the box must stay usable in the caller) | `struct Box1 { p: *mut i64 }` + `let s = shared_box_new(42); spawn(|| -> i64 { return shared_box_get(s); })` | `cannot capture 's' because it was moved` — a struct is `owned()`, so it moves into the thread. Every user type is owned; there is no `impl Copy` and no derive, so a user-defined handle cannot be copyable. |
| A pointer that may cross a thread boundary | `let s = shared_new(42)` expressed as a `*mut i64` handle, then captured | `spawn moves its captures into the thread; this capture's storage cannot cross` — `Type::Ptr`/`PtrMut` are absent from the spawn capture allowlist in `frontend/expression.rs`. |
| An integer handle that is cast back to a pointer | `let p = h as *mut i64;` | `expected Star, found Ident("i64")` — `as` only reinterprets pointer-to-pointer (`ptr_retag.ae`); there is no integer-to-pointer cast. |
| A function value stored in an aggregate (a task queue holds entries) | `struct Jobs { f: fn() -> i64 }` | `expected identifier` at the field type — `fn(..)` is only accepted in parameter and return position, not as a field type. |
| A closure value stored in an aggregate | `struct Jobs { f: T }` instantiated with `Job[fn() -> i64] { f: || -> i64 { .. } }` | `expected identifier` — `Type::Closure` has no byte layout (`c_temp` emits `void`), so closures cannot be stored, only called. |
| A generic aggregate over a handle type | `pub struct Cell[T] { val: T }` then `Cell[i64] { .. }` | Accepted. Generics work; only copy semantics is missing. |
| Whether a copy-semantics scalar handle is enough for `shared[i64]` | `shared_new`/`shared_get` reimplemented over `atomic` | `atomic` is one i64, so `shared[i64]` and `shared[bool]` could ride it — but `shared[f64]` and `shared[atomic]` cannot (no f64 atomic, and an atomic handle is a pointer that cannot be packed into an i64 cell). Partial coverage would silently narrow the documented `shared[T]` surface. |

## Decision

`pool_*`, `exec_*` and `shared_*` stay in the compiler for now and keep their
`migrate` disposition in `docs/architecture/intrinsic-allowlist.txt`. R2.4 is
recorded as **partially complete** (`cancel_*`, `timer_*` done) rather than
checked, because three families remain and the reasons are language gaps, not
missing wrappers.

The blockers, in dependency order:

1. **Copy-semantics aggregates.** A user type that is copied rather than moved
   (the charter's "recursive `Copy` eligibility" decision, §2.3) would let a
   shared box, a pool and an executor all be ordinary structs holding a
   handle. This is the single change that unblocks all three families.
2. **Pointer captures across `spawn`.** Either pointers become transferable
   (with an ownership story) or handles stay compiler-typed. Without this,
   an address-based shared box cannot reach a thread.
3. **Function values in aggregates.** A work queue stores what it will run.
   `fn(..)` field types and storable closures are both rejected today, so
   `pool_*`/`exec_*` cannot be ae source even with copy semantics.
4. **OS scheduling primitives.** `exec_*` needs cooperative yield (fibers on
   Windows, condition variables on POSIX) and `pool_*` needs worker threads
   with work stealing. Neither is exposed to ae source; both live in
   `runtime.c`.

Doing 1 without 2–4 would move `shared_*` only, and doing 1–3 would still
leave `exec_*`/`pool_*` in C. Recording the blockers keeps the ledger honest
and points the next design slice at copy semantics, which also serves M1.4
(the charter's `Copy` question) instead of inventing a one-off mechanism.

## Evidence

```
target/debug/ae check work/repro/struct_share.ae        # struct capture moves
target/debug/ae check work/repro/ptr_cross.ae           # pointer capture rejected
target/debug/ae check work/repro/fnfield3.ae            # fn(..) field type rejected
target/debug/ae check work/repro/generic_fn_field.ae    # closure in aggregate rejected
target/debug/ae check work/repro/ptr_retag.ae           # only ptr->ptr reinterpret casts exist
```

Single-platform verification (Windows x86-64). The three families' current
behavior is covered by `tests/run/shared_box.ae`, `tests/run/mutex_guard.ae`,
`tests/run/tasks_advanced.ae`, and the `tests/ui/shared_*` / `tests/ui/exec_*`
rejection fixtures, all green in the same run.

## Consequences

- R2.4 stays open with `cancel_*`/`timer_*` done; the allowlist keeps
  `shared_new`, `shared_get`, `exec_new`, `exec_run`, `pool_new`, `pool_join`
  as `migrate`.
- The next design slice that unblocks this track is copy semantics for user
  types (M1.4), not another wrapper.
- Revisit when a user type can be declared copyable and a pointer or handle
  can cross `spawn`; then `shared_*` moves first, `exec_*`/`pool_*` follow
  once function values can be stored.
- Rollback: none needed — this ADR records a decision not to change code.
