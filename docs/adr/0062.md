# ADR-62：`ae test` 增加名字过滤（`test <file.ae> [filter]`）

- 背景：ADR-43 交付的 test 运行器是「全量、顺序、失败即停」。W5 收尾后留下的明确余项是「过滤/并行」。日常使用里，改一个模块后重跑整个套件是真实的等待成本；先交付**过滤**（一次选择、零前端改动），并行另立设计。
- 决策：
  1. **过滤是测试名的子串**（cargo test 惯例），位置参数：`ae test file.ae trim`。不做正则——子串覆盖 90% 的场景，正则引入转义与跨 shell 引用问题。
  2. **空匹配是错误**：`no test functions match filter 'x'`，非零退出。拼错的过滤器不能长得像全绿——这与「不宣称」纪律同源：一个静默通过的工具在说谎。
  3. **发现先于过滤**：`discover` 仍全量扫描并校验签名，约定错误的 `test_*`（参数、返回类型、泛型）在过滤之前就被拒绝——过滤不能把坏测试藏过去。
  4. **非 UTF-8 filter 显式报错**：测试名是 UTF-8，非 UTF-8 参数不可能匹配，静默全跑会掩盖调用方的编码事故。
  5. 实现零前端语义改动：过滤只作用于 harness 的测试清单，合成 main 只包含选中测试，`ok: N passed` 计过滤后的集合；check/缓存/运行管线一行未动。
- 已排除的做法：
  - **`--filter=NAME` 长选项**：位置参数是 cargo/pytest 用户的肌肉记忆，长选项留给将来真正需要多参数时再设计（本轮末位参数即过滤，无歧义）。
  - **正则/glob**：见决策 1；glob 的 `*` 在 shell 里要先转义，跨平台 shell 差异会让「同一个过滤命令」在两平台写法不同。
  - **并行执行**：失败即停的顺序输出是 v1 行为；并行需要先设计输出聚合、失败语义与资源上限，另立工作项。
- 资源成本（归档 `bench/results/2026-11-12-windows-testfilter/`）：
  - **验证**：36 单元（+1 harness 过滤测试）+ 174 集成（test_runner 扩展 3 段）全通过；`--leak` 33 用例基线不变；fmt 43 文件；41 程序 `check`。
  - **编译器**：main.rs 分支 +2 参数、harness `prepare` 增加过滤参数；生成 C 对任何程序零变化（过滤不触碰代码生成）。
- 边界（对外表述不得越过）：
  - 不宣称「测试并行/`--list`/覆盖率」已可用：本轮只有子串过滤。
  - 过滤不改变「失败即停」：选中集合内第二个失败仍不会继续跑第三个。
  - `ok: N passed` 的 N 是**过滤后**的数量；不宣称它是套件总数。
- 验证：Windows 36 单元 + 174 集成、`--leak` 33 用例 PASS（基线 2 块）、fmt 验收 43 文件、41 程序 `check`；归档 `bench/results/2026-11-12-windows-testfilter/`。Linux 回填（同一源码树 9259b65，`bench/results/2026-11-12-linux-testfilter/`）：36 + 174 全通过、`--leak` 33 用例基线 0 块、`--sanitize` 33 用例 0 报告、fmt 43 文件幂等、CLI 过滤行为两平台逐字一致（`filter-cli-demo.txt` 原样记录：过滤 ok: 2 passed / 空匹配 exit 1 / 无过滤 ok: 3 passed）。状态：**双平台验证**（2026-11-12）。
