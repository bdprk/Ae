# ADR-67：语言设计宪章——Rust 的安全模型 + Go 的简洁与并发

- 状态：已接受
- 日期：2026-11-12
- 关联里程碑：M0.1（`docs/plan.md` §2）

## 背景

ADR-1~66 以“增加内建 + 运行时微优化”推进，产生了按元素类型手写的容器家族（`vec`/`vec[string]`/`vec[f64]`、两种 map）、9 个预置结果枚举与数十个全局内建。这条路线线性膨胀，且偏离了“同时具备 Go 与 Rust 优点”的目标：Go 的并发/接口/包管理与 Rust 的静态借用、泛型容器、闭包迭代器均缺失。

## 决定

采纳 `docs/plan.md` §2 为语言设计宪章，核心为十条硬规则：

1. 容器、结果类型、迭代器一律泛型实现，禁止新增按类型手写的家族与预置结果枚举。
2. 编译器内建只保留无法用语言表达的原语，其余进入标准库并用方法语法调用。
3. 借用/移动安全由编译期给出，运行时检查不作为兜底。
4. 生命周期默认推断。
5. 并发无函数染色：结构化作用域内 `spawn` 普通函数。
6. 错误只用 `Result[T, E]` + `?`；`panic` 仅用于不变量违反。
7. 开发与发布语义相同。
8. 按需付费：不用的运行时组件不链接。
9. 规范先行。
10. 证据先行。

## 后果

- 修改上述规则须另立 ADR。
- 现有内建与家族在 M1 迁移为标准库泛型实现（见 ADR-68 冻结清单）。
- 对标对象改为 Go/Rust；Gojo 不再作为验收基线。
