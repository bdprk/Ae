# ADR-12: Read-Only Borrowed Parameters (`&string`, `&vec[string]`) and Directory Traversal

- **Background**: Section §19.3 of the proposal lists "cross-platform batch file organization and directory traversal" as a primary acceptance task. However, the language previously could only read and write single files, and function parameters were strictly moved by value—recursive traversal requires reusing the same path/pattern string repeatedly, and passing by value is immediately rejected inside loops due to collection movement rules.
- **Decision**:
  1. Introduce a new parameter type `&string`, bound as a `string view`: At the call site, the argument expression is wrapped as `AE_VIEW(...)`, incurring no move and no copy; the argument can be an owned string, literal, view, or a `vec[string]` element. Inside the function body, it acts as a regular view (`len`, `contains`, `slice`, `==`, `print`, and `+` are available); it cannot be returned or forwarded to parameters expecting a value by ownership.
  2. Introduce a new parameter type `&vec[string]` (`Type::StrVecRef`), isomorphic to the existing `&vec`: read-only, supports `len`, element view retrieval via `v[i]`, iteration via `for x in v`, and forwarding as `&vec[string]`; push, pop, mutation, and movement are prohibited.
  3. Borrowed values have no independent storage: `let q = borrowed_param;` is rejected (a loophole that previously existed for `&vec` as well, which would generate invalid C). Borrows can only exist as parameters or pattern bindings.
  4. Open up enum payloads to support `vec` and `vec[string]`, binding them in `match` arms as `&vec` and `&vec[string]` respectively; payloads similarly cannot be moved out.
  5. Add filesystem builtins: `try_list_dir(path) -> DirResult{Ok(vec[string]), Err(string)}` (returns entry names only, excluding `.` and `..`, sorted in lexicographical byte order to ensure cross-platform consistency), `path_exists(path) -> bool`, and `path_is_dir(path) -> bool`. On Windows, these use `FindFirstFileW`/`GetFileAttributesW` (converting UTF-8 paths to UTF-16); on POSIX, they use `opendir`/`stat`.
- **Rationale**: Recursion and repeated calls require parameters that are "borrowed rather than moved." Manually writing `slice(x, 0, len(x))` to create copies is both slow and easily forgotten. Views are already a mature representation within the language (ADR-8); exposing them as parameter types incurs zero additional runtime cost. `try_list_dir` reuses the result value pattern from ADR-11, making non-existent directories a recoverable error rather than a process termination—file organization scripts must be able to skip permission-denied directories and continue execution.
- **Alternatives Considered & Rejected**:
  - **Implicit borrowing for `fn f(s: string)`**: This would make the "move by value" rule dependent on the shape of the call site, undermining the predictability of existing move semantics; explicit `&string` is much clearer.
  - **`list_dir(path) -> vec[string]` (terminating on failure)**: Traversal inevitably encounters permission-denied or race-deleted directories, making termination unacceptable.
  - **Returning full paths instead of entry names**: Concatenation strategies (separators, relative/absolute) belong to the caller; the runtime should not make assumptions.
- **Consequences and Limitations**: `&string` is a shallow borrow "valid during the call," with no cross-function lifetime checking; hence it cannot be returned or stored in variables. The same applies to `&vec[string]`. Directory traversal does not return file metadata (size, timestamps), is non-recursive, and does not distinguish symbolic links. Sorting is based on raw byte order (non-localized), solely for reproducibility. The `vec[string]` payload causes the C layout of `DirResult` to contain `ae_strvec`, whose deallocation is handled by the enum deallocation routine.
