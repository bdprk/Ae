# ADR-1: C Backend as a Replaceable Bootstrapping Strategy

- Background: Developing a native machine code backend from scratch requires covering ABIs, object files, relocation, and debug information for two platforms, which incurs high costs.
- Decision: The first-generation compiler generates C11 and invokes a supported C toolchain (Windows GCC/MinGW, Linux GCC/Clang); generating C serves as an internal interface that can be replaced wholesale.
- Rationale: This is the fastest way to obtain native binaries and a correctness baseline for both platforms, allowing engineering effort to be concentrated on language semantics and the type checker.
- Consequences: Build times are constrained by the external C compiler; generated C code must avoid undefined behavior (using checked runtime functions to support semantics). When end-to-end data indicates that C compilation is the primary bottleneck and caching proves insufficient to meet targets, the backend will be re-evaluated (see roadmap phase D).
