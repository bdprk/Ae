# ADR-13: Path Algebra and Built-in File Metadata / Organization Operations

- Background: Following ADR-12, directories can now be traversed recursively. However, the file organization acceptance task in §19.3 still requires three missing capabilities: first, path concatenation (previously limited to `dir + "/" + name`, which easily produces erroneous paths like `dir//name` or paths without separators); second, reading file size/timestamp (otherwise impossible to "categorize by size/time"); third, moving, copying, deleting, and creating directories (otherwise files can only be read, not organized). ADR-12 explicitly listed "not returning file metadata" as a limitation, and this ADR serves to close out that limitation.
- Decision:
  1. Add pure string path functions `path_join(dir, name)`, `path_name(path)`, and `path_parent(path)`. No normalization or file system access is performed; the output uniformly uses `/`; `path_join` completely replaces `dir` when encountering an absolute `name`; `path_parent` returns an empty string for paths without separators.
  2. Add preset enums `FileResult{Ok(i64 size, i64 modified, bool is_dir), Err(string)}` (ID 4) and `StatusResult{Ok, Err(string)}` (ID 5). These two, along with the four result enums from ADR-11, are preset in the same batch, validated in the same order, and share the same migration plan (to be moved entirely to the stdlib once generics `Result<T, E>` land).
  3. Add `try_file_info(path) -> FileResult`: `modified` is uniformly defined as "seconds since the Unix epoch". On Windows, FILETIME's 100ns counts are converted to the same standard (`/10000000 - 11644473600`), allowing direct comparison of values across both platforms.
  4. Add `try_copy_file`, `try_rename_path`, `try_remove_file`, `try_create_dir`, and `try_remove_dir`, all returning `StatusResult`. `try_create_dir` has `mkdir -p` semantics; `try_remove_dir` only deletes empty directories.
- Rationale: Path concatenation has an extremely high error rate (separators, absolute paths, empty arguments); making it a built-in is more reliable than manual concatenation in every example. Metadata uses seconds instead of nanoseconds because i64 nanoseconds can only represent up to the year 2262, and struct field widths vary across platforms, whereas second-level integers are unambiguous on both sides. Write operations return `StatusResult` instead of reusing `WriteResult` because "delete/rename/create directory" has no natural return value; using an `Ok` with an empty payload expresses this faithfully, avoiding the fabrication of a meaningless count.
- Rejected Alternatives:
  - **`try_remove_file` directly calling `remove()` on POSIX**: It would delete empty directories, causing the same program to behave differently across platforms; instead, we explicitly check `is_dir` and return an error, preferring to lose a convenience rather than introduce platform divergence.
  - **Recursive deletion `try_remove_all(path)`**: Once arguments are miscalculated, it is irreversible, and the current language lacks interactive capabilities like "confirmation". Organization scripts should list entries and delete them one by one (as demonstrated in `examples/file_tidy.ae`).
  - **`path_parent` returning `.` for relative paths**: This would cause `path_join(".", "a")` to produce `./a`, concealing the information of whether a parent directory exists; returning an empty string allows the caller to explicitly choose a default value.
  - **Path normalization (resolving `..`, collapsing `//`, case unification)**: Symlinks and Windows case-insensitivity make normalization results dependent on the actual file system, which belongs to I/O semantics rather than string semantics, leaving it for a subsequent explicit `try_canonicalize`.
  - **`try_create_dir` erroring when the directory already exists**: Callers typically just want to "ensure it exists", and erroring would force every call site to write retry branches.
- Consequences and Limitations: The six result enums permanently occupy IDs 0–5; 9 new reserved names are added. Copying does not preserve permissions/timestamps; cross-volume renaming on Windows relies on `MOVEFILE_COPY_ALLOWED` (cross-volume POSIX `rename` will fail and faithfully return `Err`); recursive deletion and directory size aggregation are not provided; metadata does not include permission bits or access times; `path_*` does not handle `~` expansion or environment variable substitution. Simultaneously, a preexisting defect is fixed: owned temporary arguments for `read_file`/`write_file`/`bytes` were previously unreleased (`write_file("a" + b, ...)` would leak the path buffer); they are now consistent with other built-ins, releasing temporary values after the call.
