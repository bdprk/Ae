# ADR-72: Incremental migration to structured source locations and diagnostics

- Status: in progress (foundational types and lexical errors implemented; verified on Windows)
- Date: 2026-11-12
- Milestones: M0.4–M0.5

## Context and decision

The existing frontend passes errors as strings, forcing the command-line JSON output to parse text and preventing reliable support for multiple labels and errors. Introduce `ae-span` for source ranges validated against UTF-8 boundaries, line and column positions, diagnostics, primary and secondary labels, and suggestions. Preserve the existing location convention: lines and columns start at 1, and columns count Unicode scalar values.

The lexer provides a structured diagnostic interface; the existing interface formats those diagnostics as before. File loading, parsing, the current single-pass semantic checks, and `check --json` pass source diagnostics as structured values, including the path of an imported file. Loader errors without source locations still travel as strings. Do not invent error codes or suggestions, and do not claim structured diagnostic support for stages that have not been migrated.

## Verification and next steps

The workspace tests pass on Windows. Added tests cover UTF-8 boundaries, CRLF, end of file, JSON diagnostics from imported files, and JSON snapshots; the generated output of 44 examples matches the baseline. Tokens now retain half-open byte ranges, allowing parser diagnostics at known tokens to identify a full token without changing their displayed start position. Limited lexical recovery reports multiple unexpected characters in a single tokenization pass and can collect lexical errors from independent sibling imports. Function-body recovery checks ordinary functions and impl methods against isolated declaration-state copies, as specified in `spec/diagnostics.md`. Recovery within a body and in declarations, structured error codes, richer labels and suggestions, and the remaining driver paths still need work. Linux verification remains pending; M0.4 and M0.5 are not complete.
