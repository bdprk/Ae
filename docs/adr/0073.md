# ADR-73: Distinguish circular imports from completed imports

- Status: implemented (verified on Windows; Linux verification pending)
- Date: 2026-11-12
- Related: M0 correctness fix; module rules in `docs/current-language.md`

## Context

The language documentation specifies depth-first loading, loading each file once, and rejecting circular imports. The original loader tracked only a set of visited files, so it rejected diamond dependencies just like actual cycles, contrary to the documented behavior.

## Decision

Track two states keyed by filesystem-canonicalized paths: loading and loaded. Encountering a loading file is a cycle; encountering a loaded file reuses the previous result. Cross-file name conflicts, visibility rules, and the rejection of actual cycles remain unchanged.

This correctness fix implements existing documented semantics and is an explicit exception to M0's behavior-preserving refactoring. It did not change generated output for existing valid examples.

## Verification

On Windows, an end-to-end test covers diamond dependencies, different relative paths to the same file, direct repeated imports, a single `deps` entry, and rejection of recursive imports. All workspace tests passed. The exit status and output of `emit-c` for 44 existing examples match the pre-migration baseline. Linux verification remains pending.
