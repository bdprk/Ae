# ADR-71: Extracting the Lexer Crate

- Status: Implemented (Verified on Windows; Pending verification on Linux)
- Date: 2026-11-12
- Associated Milestone: M0.3–M0.4

## Background and Decision

In the transition workspace of ADR-70, the lexer and its token types were mechanically migrated into `ae-syntax` for use by the existing parser and test utilities. Lexical rules, token positions, and diagnostic strings remain unchanged. This crate currently implements only lexing and does not imply that the planned parser, AST, formatter, or error recovery have been migrated or completed.

Existing helper functions for positions and diagnostic strings have been migrated alongside the lexer; these are not yet a unified `Span`/`Diagnostic` model. Establishing a structured source position and diagnostic model remains a task for M0.4. `ae-compiler` continues to serve as a transition crate to avoid misinterpreting single-pass parsing/checking as a fully implemented HIR.

## Verification

`cargo test --workspace` passed on Windows; the exit codes, stdout, and stderr for the `emit-c` of 44 sample files are consistent with the SHA-256 records from before the split (two module files were rejected as entry points). Linux verification is pending.

During the migration, an independent bug was fixed: the original implementation crashed when calculating positions using an empty source file and non-zero offsets during malformed import header formatting. It now uses the actual source file and avoids redundant filename prefixes. UI snapshots cover invalid paths following non-ASCII comments and missing semicolons.
