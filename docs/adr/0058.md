# ADR-58: Make Map Miss Reason Text a Read-Only Constant, Eliminating Miss Allocations

- Background: ADR-56 attribution measured that "`map_get` miss returns `Err(reason_string)`, allocating a string on every miss" (1M misses on an empty table cost 6.9 ms more than key baseline, approx. 6.9 ns/miss). At the time, this was left untouched because "an `Err` carrying an owned string is a language-level design decision." Following ADR-57, map performance still lagged Rust by about 5%, while memory usage had already surpassed it. We therefore revisited this last remaining allocation on the miss path.
- Key Observation: The text is a fixed constant `"key not found"`, whose content and length never change. The only obstacle is that "owned strings must be freed upon release." By placing it in read-only data, the release path simply needs to skip it **by identity (address)**. All other semantics (content, `len`, `==`, `+` concatenation, copying into `vec[string]`, moving with enums, `?` propagation) remain completely unchanged—releasing is the only place that needs to recognize it.
- Decision:
  1. Define `static const char ae_missing_key_text[] = "key not found";` in `runtime.c`; `ae_map_get` directly uses it to construct `ae_string` on a miss (still an owned value, content and length unchanged).
  2. Modify `ae_str_release` to: `if (slot->ptr && slot->ptr != ae_missing_key_text) ae_free(slot->ptr);`. Equality comparison on unrelated pointers is well-defined (C11 6.5.9p6), whereas range comparisons (`<`/`>`) are undefined behavior. Therefore, identity comparison is used instead of address ranges.
  3. Move the release function up to follow the definition of `ae_string`, removing its original forward declaration; retain the `line`/`column` parameters in `ae_map_get` to maintain signature consistency for built-in functions, marking them as unused via `(void)`.
  4. Fix a binary size issue along the way: the comment on `ae_string` referenced the name `ae_str_cat`, and identifiers in top-level text are treated as roots by the tree-shaker (the second lesson of ADR-50). Consequently, **every program** retained the entire string concatenation cluster. Changing it to "Concatenation" saves 1,480 bytes on `print(1)`.
- Alternative Approaches Ruled Out:
  - **Address range check** (`ptr >= text && ptr + n`): Comparing pointer relationships between different objects is undefined behavior, and the optimizer can legally fold it.
  - **Global mutable `ae_immortal` pointer** (`map_get` writes, `release` reads): Saves less than 100 bytes while introducing mutable global state, requiring visibility handling in future multi-threaded scenarios; static constants do not have this issue.
  - **Allocate once on first miss, reuse thereafter**: The same pointer would be owned by multiple `Err` values simultaneously, meaning the first release would cause the rest to dangle; adding reference counting would shift the cost back to the runtime and alter the leak ledger.
  - **Change the `IntResult::Err` payload to a view or error code**: This is a language semantic change (the public shape of `map_get`), which is out of scope for this round. Fixed text + identity skipping achieves the same gains without modifying the language.
  - **Constant placed at top level + three-line comment** (First implementation): Comments falling into "function-less units" are retained forever, increasing `print(1)` size by +484 bytes. The current approach places the array adjacent to the release function and moves explanatory comments inside the function body so they are stripped along with the function.
- Resource Costs (addressing each acceptance question in §21):
  - **Runtime CPU** (Linux, 21 interleaved runs, ratios calculated pairwise): Miss probe 43.06 → 24.26 ms, **1.764×** (other two rounds in the same session: 1.775× / 1.789×, pairwise ratio range 1.71–1.91); hit probe 27.11 → 26.93 (1.012×), with the same-binary control group at 1.006× / 1.002×, indicating the hit path remains unchanged. Allocations for 1M misses dropped from 1 million to 0; the `miss - hit` difference metric changed from +15.9 ms to −2.7 ms (probing ends at an empty slot on a miss, making it even cheaper than a hit).
  - **Peak Memory**: 1.36 ↔ 1.43 MB, with opposite directions between rounds (another sampling showed 1.54 → 1.35), judged to be sampling noise; no reduction is claimed.
  - **Executable Size**: Linux +8 bytes; Windows PE for the two probes −521 bytes (due to the comment root fix stripping the concatenation cluster, not from this text itself).
  - **Generated C**: miss 22,928 → 23,019, hit 22,926 → 23,017 (+91 each); `print(1)` 15,302 → 13,822 (−1,480 due to comment root fix).
  - **Allocations/Leaks**: `--leak` 31 test cases, Windows 2 blocks / Linux 0 blocks baseline unchanged; the new test case `missing_map_key_text_survives_every_owned_string_path` leaves no residual blocks after 1000 misses.
  - **Safety Semantics**: No checks disabled; release remains idempotent, and static text is never freed.
- Boundaries (external claims must not exceed):
  - Do not claim "maps got faster": Hit path is 1.012× (control 1.006×); gains are strictly on paths that **miss and require a reason**.
  - Do not claim to surpass Rust: Same probe Rust 8.58 ms vs. AE 24.26 ms (approx. 4.9×). Rust returns an `Option` (no payload), whereas AE constructs a 24-byte `Result` enum on every call and goes through checked arithmetic. This is an issue with the built-in call shape, which cannot be resolved in this round; logged as a candidate for the next round.
  - Only fixed text in `map_get` behaves this way; error texts for files, JSON, processes, etc., carry paths or system messages and remain dynamically allocated.
  - Constant objects (14-byte array + declaration) reside in the resident top-level text of **all** programs, totaling approx. 50 bytes. While `print(1)` dropping from 15,302 to 13,822 is a net gain, it cannot be credited to the "miss optimization."
- Process Discoveries:
  1. **Literal arguments are owned temporary values allocated on every call**: The first version of the probe wrote `"absent"` inside the loop, allocating keys 1M times which took ~18 ms and compressed the measured difference by half. Moving the key outside the loop revealed the 1.76× speedup. For any future "per-call" probe, first verify there are no other allocations inside the loop.
  2. **Function names in comments act as tree-shaking roots** (already noted in ADR-50 and ADR-55): This time, the comment on `ae_string` mentioned `ae_str_cat`, forcing `print(1)` to continuously carry ~1.5 KB of the concatenation cluster. The fix is not to delete comments, but to avoid writing function names in top-level text.
  3. **Same-binary control groups are indispensable**: The initial observation that the hit path was "4% slower" was correctly diagnosed as layout and noise—rather than new logic—thanks to the same-binary control group (1.006× / 1.002×).
- Verification: Windows 35 units + 165 integration, `--leak` 31 test cases PASS (baseline 2 blocks), 38 examples passed via `check`; Linux 35 + 165, `--leak` 31 (baseline 0 blocks), `--sanitize` 31 test cases 0 reports, 38 examples passed; four-workload suite run in the same session (interference present on local machine, for reference only). Added new integration test `missing_map_key_text_survives_every_owned_string_path` covering reads, left/right concatenation, moving into functions, `vec[string]` copying, and `?` cross-function propagation. Archived under `bench/results/2026-11-11-{windows,linux}-map-missing/`.
