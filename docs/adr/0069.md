# ADR-69: Splitting Frontend into Submodules by Responsibility (Zero Behavioral Changes)

- Status: Implemented (Single platform: Windows)
- Date: 2026-11-12
- Associated Milestone: M0.3

## Context

`src/frontend.rs` is approximately 330 KB / 5,333 lines long. Lexing, parsing and checking, C emission, and runtime pruning are all mixed in a single file, making it difficult to collaborate on and evolve toward HIR/MIR.

## Decision

Mechanically relocate code to `src/frontend/`:

| File | Responsibility |
|---|---|
| `mod.rs` | Shared types (Token/Type/Expr/Statement/Definitions), prelude, module loading, and public API |
| `lexer.rs` | Lexing and source locations |
| `parser.rs` | Parser + single-pass semantic checking (`impl Parser`) |
| `codegen.rs` | Statement/expression to C translation |
| `c_output.rs` | C type mapping, runtime pruning, and whole-program C assembly |

Submodules access parent module private items via `use super::*`; cross-module calls are promoted to `pub(super)`. No logic is changed.

Future steps (M0.3, phase 2) will involve splitting into cargo workspace crates when introducing HIR; we are not splitting into crates currently because the Parser is tightly coupled with type definitions, and splitting now would require excessive `pub` exposure with no tangible benefit.

## Evidence

- `cargo test --release`: All 36 unit tests and 179 integration tests passed (Windows, MinGW GCC 16.2).
- The `emit-c` output for all 44 `examples/**/*.ae` files is byte-for-byte identical before and after the split (SHA-256 comparison).
- Linux backfill pending.

## Consequences

- `parser.rs` remains approximately 2,600 lines long; it will be further separated into "parsing" and "checking" components when HIR is introduced in M1.
