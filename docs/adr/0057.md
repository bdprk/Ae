# ADR-57: Moving Map State Bits Out of Slots, Reducing Slot Size from 32 to 24 Bytes

- Background: ADR-56 traded "table doubling" for map load times of 1.17x, with the trade-offs documented in the ADR—approximately 64 bytes of slot overhead per element, a peak load of 2.44 -> 3.43 MB, and leaving a "24-byte slot + separate state array" as the next step. This step implements that.
- Key observation: The key pointer, key length, and value occupy 24 bytes, while an additional state byte caused padding to a 32-byte slot. Probing most often needs the state before reading the key.
- Decision: Keep the key and value in `ae_map_slot` and store one state byte per slot in a parallel array. Update lookup, insertion, increment, removal, growth, release, and key enumeration to use that array.
- Rejected: Packing state into the visible key length and adding an in-slot hash tag.
- Historical evidence: The recorded Linux session reported peak memory of 3.43 MB before and 2.90 MB after, with map timings approximately unchanged (59.84 ms and 59.36 ms). The slot storage calculation fell from 32 to 25 bytes per slot including the separate state byte. See `bench/results/2026-11-11-linux-map-states/` and `bench/results/2026-11-11-windows-map-states/`.
- Boundaries: This is an internal layout change; the recorded data supported a memory reduction, not a general speed claim. Peak memory includes more than the map table.
- Verification recorded at the time: Windows and Linux tests, leak checks, examples, and Linux sanitizers. A test covers key enumeration after removal and reuse of slots.
