# ADR-26：JSON 路径查询（只读）

- 背景：阶段 B 第 6 项的验收要求「常见文本/JSON 工作流可运行」，阶段 E 第 1 项把 JSON/CSV 列为基础 API。没有它，读一份 API 响应或配置文件只能靠 `split` + `contains` 手写，一旦出现嵌套对象、转义引号或数组就不可靠——而这正是「脚本语言该做的事」里最常出现的一种。
- 决策：
  1. 只做**只读路径查询**，五个内建：`json_get(text, path) -> ReadResult`、`json_int(text, path) -> IntResult`、`json_bool(text, path) -> BoolResult`、`json_len(text, path) -> IntResult`、`json_has(text, path) -> bool`。
  2. 路径语法：`key`、`key.sub`、`key[2].sub`、`[0].key`；空路径表示整个文档。键按**解码后**的字节比较（对象键里的 `\uXXXX` 先还原再比）。
  3. `json_get`：字符串值解码全部转义（含 `\uXXXX` 与代理对，输出 UTF-8）；数字、`true`/`false`/`null` 返回**原文**；数组与对象返回**原始片段**（可直接保存或再解析）。
  4. `json_int` 只接受没有小数点与指数的整数，溢出 i64 报错；`json_bool` 只接受 `true`/`false`；`json_len` 只接受数组与对象。
  5. 新增预置枚举 `BoolResult{Ok(bool), Err(string)}`（编号 6）——用 `IntResult` 加 0/1 会把「假」和「没有」混在一起。
  6. 每次调用重新扫描文档；嵌套深度上限 64；路径先在文档之前单独校验，路径写错就报路径错误。
- 理由：不引入 JSON 值类型，是因为那会把容器的所有权、递归布局、访问语法、错误传播一次性塞进类型系统，与「低内存、确定性释放、编译期拒绝移动」的既有模型正面冲突；路径查询把复杂度留在运行时，返回值仍是既有的结果枚举，用 `match` 处理，语言本身一个语法都不用改。分成三个返回类型而不是「统一取字符串再转换」，是因为**「没有这个字段」和「字段类型不对」必须能区分**——这正是 ADR-22 拒绝让 `env` 返回 `Option` 的同一条理由。代理对要还原，否则中文与 emoji 的 JSON 在 AE 里会变成字面的 `\ud83d\ude00`，而原始字段值是任何真实 API 都会给出的东西。
- 已排除的做法：
  - **`json` 类型 + `doc["key"]` 索引**：见上，需要新类型、新所有权规则、新错误语义。
  - **解析成文档句柄（一次解析、多次查询）**：需要「句柄类型 + 释放点」；而配置级输入重扫的成本是微秒级（16 个字段 × 10 KB），不值得为此增加一种拥有型资源。
  - **`json_get` 统一返回字符串、由调用者 `parse_int`**：丢掉「字段类型错误」的诊断，且 `parse_int` 对 `"12"` 与 `12` 无从区分。
  - **实现 JSON 写入/序列化**：构造器、转义、键序都需要设计；`join` 与字符串拼接已能生成简单 JSON，等结构化输出需求明确再做。
  - **严格 JSON 校验**（数字语法、拒绝重复键、拒绝尾随逗号）：读取器按「找到值就走」的宽松口径实现，严格性由 `json_int`/`json_bool` 在转换时保证；文档写明这一点，避免使用者以为 `json_get` 是验证器。
- 后果与限制：没有写入、没有浮点（`json_int` 拒绝 `1.5`）、没有遍历回调——遍历数组要 `json_len` + `[i]` 循环（可行但不优雅）；键名里含 `.` 或 `[` 无法表达；重复键取第一个；不跳 UTF-8 BOM；不校验整个文档，只在路径经过的地方探测语法错误；文档必须完整驻留内存（`read_file`/`read_stdin`）。新增 2 个端到端测试（正常路径与 10 类错误）与 `examples/json_report.ae`，并把该示例纳入分配计数校验（`blocks=2`，无泄漏）。
