feat: R2.4a migrate cancel_*/timer_* to std/sync + std/task (ADR-0224)

The seven cancellation and timer builtins leave the compiler surface and become
ordinary ae source over cell_*:

- std/sync/cancel.ae: one atomic cell (0 active, 1 cancelled, 2 completed);
  trigger and complete CAS only from 0, is_set reports only 1.
- std/task/timer.ae: a plain struct { deadline, cancelled } passed as &Timer;
  the cancelled flag is a shared atomic, so copied timers agree.

Semantics match the retired builtins: a cancelled timer is never ready, cancel
succeeds once and only before the deadline, and a negative delay clamps to 0.

Two real defects surfaced while porting:

- cell_* used an early return out of identifier dispatch, bypassing the shared
  infix tail, so cell_load(c) == 1 was reported as expected Semi (c33d865
  binds the arms as value expressions).
- fake_clock.ae borrowed &deadline inside task_spawn, which moves captures; the
  fixture now copies the timer into a local. The rule itself is correct.

The allowlist loses its seven lines; RESERVED, parse arms, codegen, MIR,
interp, runtime.c and the LSP tables are swept in the same slice.
tests/ui/timer_non_handle.ae now imports std/task/timer.ae and passes a wrong
argument type, pinning a real type diagnostic instead of "unknown function".

cargo test --workspace: 14 bin + 319 execution + 3 snapshot + 11 LSP +
44 compiler + 2 span + 58 syntax = 453 passing on Windows; ui and ui-json
snapshots green.
